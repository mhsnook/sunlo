# Sunlo API

A Cloudflare Worker at `api.sunlo.app` for endpoints that need Cloudflare bindings. It is a [Hono](https://hono.dev) app with one route today:

| Route                  | Binding                 | Does                                                                                                      |
| ---------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------- |
| `POST /extract-phrase` | `AI`, `EXTRACT_LIMITER` | Reads the text in one image with a vision model and returns phrases with transliteration and translation. |

## Auth

Every route requires the `Authorization: Bearer <access token>` header from a signed-in Sunlo session. The worker checks it with `supabase.auth.getClaims()`, which verifies the signature against the project's JWKS, and requires `role = 'authenticated'`, so the public anon key is rejected. The worker has no database access.

## Configuration

| Name                  | Kind    | Set in                         | Purpose                                                          |
| --------------------- | ------- | ------------------------------ | ---------------------------------------------------------------- |
| `SUPABASE_URL`        | secret  | `.dev.vars`, `wrangler secret` | Project to verify tokens against.                                |
| `SUPABASE_ANON_KEY`   | secret  | `.dev.vars`, `wrangler secret` | Required by the Supabase client. It is public, not a credential. |
| `ALLOWED_ORIGINS`     | var     | `wrangler.jsonc`               | Comma-separated CORS allow-list.                                 |
| `PHOTO_EXTRACT_MODEL` | var     | `wrangler.jsonc`               | Workers AI model id for `/extract-phrase`.                       |
| `EXTRACT_LIMITER`     | binding | `wrangler.jsonc`               | 10 requests per user per minute.                                 |

The web app reads the worker's URL from `VITE_API_URL`. `VITE_PHOTO_EXTRACT_USE_MOCK=true` makes the web app return canned results without calling the worker; `pnpm dev:local` and `pnpm build:test` set it.

## Commands

Run these from the repo root:

```bash
pnpm api:dev      # http://localhost:8787
pnpm api:check    # regenerate worker-configuration.d.ts, then typecheck
pnpm api:deploy   # wrangler deploy to Cloudflare
pnpm --filter @sunlo/api test
```

`pnpm api:dev` needs `apps/api/.dev.vars` (copy `.dev.vars.example`). The `AI` binding always runs remotely, so it also needs `wrangler login`, or `CLOUDFLARE_API_TOKEN` in a non-interactive shell. To work on everything except the model call, run `wrangler dev --local` from `apps/api`; requests that reach the model then fail.

## Deploying

The custom domain needs the `sunlo.app` zone on the same Cloudflare account. Set both secrets once with `wrangler secret put SUPABASE_URL` and `wrangler secret put SUPABASE_ANON_KEY`. Set `VITE_API_URL=https://api.sunlo.app` in the web app's build environment.

`worker-configuration.d.ts` is generated by `wrangler types` and not committed.
